# АРМ Кафедра — управление магистратурой

Учебный веб-проект по варианту 13. Интерфейс на русском языке. Python 3.10 или новее, SQLite и стандартная библиотека Python: установка pip-пакетов не нужна.


## Обновление 2.0

Проект настроен для **Международного Университета Астаны / Астана Халықаралық университеті**. Название кафедры и ФИО подписантов не заданы: заполните их в разделе «Реквизиты вуза».

- Новый главный экран, быстрые действия, обновлённая навигация и адаптивное оформление.
- Центр документов: индивидуальный план, лист ежегодной аттестации, отчёт о научной работе.
- Реквизиты и заголовки документов на русском или казахском языке. Содержимое пользовательских записей сохраняется на языке ввода, без автоматического перевода.
- Неизменяемый реестр: внутренний номер, дата, версия и снимок данных на момент подготовки.
- Экспорт в Word; просмотр и печать на A4, сохранение в PDF через диалог печати браузера.
- Помощник с локальными сводками и подключением языковой модели через OpenAI Responses API.
- Предложение сформировать план: просмотр действия → подтверждение пользователем → создание версии. Ответ сам по себе записи не меняет.

### Как подготовить документ

1. Откройте «Реквизиты вуза» и заполните кафедру на нужных языках, город, должность и ФИО согласующего.
2. Подготовьте исходные данные: магистранта, тему и план либо аттестацию.
3. В разделе «Документы» выберите вид, магистранта, учебный год, язык и основание. Для индивидуального плана выберите его версию.
4. Нажмите «Создать в реестре». Откройте «Просмотр / PDF» либо скачайте Word.
5. Проверьте сведения и передайте проект на утверждение в своём вузе.

**Статус документов:** это проекты документов университета, а не документы от имени государства. Подтверждённый бланк вуза не предоставлен; шаблоны не заявляются как утверждённые или сертифицированные формы. Государственный герб, печать и подписи не воспроизводятся. ЭЦП и интеграция с НУЦ РК не реализованы. Внутренний номер не означает государственную регистрацию. Изменение реквизитов не меняет уже сохранённые документы; для исправления создайте новый проект. Документ Word содержит номера страниц и таблицы с повторяемыми заголовками.

### Подключение ИИ

Без ключа доступна **локальная аналитика по правилам**. Это не языковая модель. Для настоящих ответов ИИ задайте переменные окружения в терминале перед запуском:

```powershell
$env:OPENAI_API_KEY = 'ВАШ_КЛЮЧ_API'
$env:OPENAI_MODEL = 'ИМЯ_ДОСТУПНОЙ_МОДЕЛИ'
python app.py
```

Укажите модель вашего API-проекта, поддерживающую Responses API и Structured Outputs. `.env` автоматически не загружается. Не вставляйте ключ в чат помощника и не коммитьте его в Git. В интерфейс передаётся только состояние подключения и имя модели.

В «ИИ-помощник» выберите магистранта (или всю кафедру), учебный год и режим. Для облачного запроса требуется явная отметка согласия. В OpenAI отправляются **введённый вопрос и сводка выбранных данных**. Сводка исключает ФИО, email, названия тем, статей и идентификаторы; вопрос отправляется как введён, поэтому не включайте в него персональные или конфиденциальные сведения. Запрос использует `store: false`; это не обещание полного отсутствия обработки или хранения у провайдера — применяются его условия и политика данных.

Помощник получает агрегаты экзаменов и публикаций, сроки аттестаций и состояния работ за выбранный период. Публикации отбираются по двум календарным годам, поэтому период нужно проверить. Каждый облачный запрос самостоятельный: предыдущая переписка не передаётся. Решения об оценках и аттестации помощник не принимает.

Для плана выберите конкретного магистранта. В локальном режиме отметьте «Предложить создание плана»; в облачном попросите об этом в вопросе. Предложение действует 15 минут и связано с текущим входом. Подтверждение одного предложения повторно возвращает уже созданный план. Утверждение плана и выпуск документа выполняются отдельно пользователем.

**Проверка интеграции:** контракт API и обработка ответов проверены на имитации провайдера. Реальный платный запрос не выполнялся: рабочий API-ключ не предоставлен. Ошибки подключения отображаются без раскрытия ключа.

### Обновление существующей установки

Остановите сервер, сохраните резервную копию всего `data/`, обновите исходники и запустите приложение. Новые таблицы реестра, настроек и предложений помощника создаются в существующей `AuditDb.sqlite3`; остальные шесть баз не переносятся и не удаляются.

### Источники для реализации

- [Правила документирования, приказ №236, ИПС «Әділет»](https://old.adilet.zan.kz/rus/docs/V2300033339) — ориентир по реквизитам и документированию; соответствие конкретному виду документа и правилам вуза требует отдельного согласования.
- [OpenAI Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses) — серверное подключение модели.
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) — формат ответа помощника.

## Быстрый запуск Windows

1. Скачайте проект через **Code → Download ZIP** и распакуйте архив или клонируйте репозиторий: `git clone https://github.com/DizzDer/cafedra.git`.
2. Запустите `start.bat` двойным щелчком.
3. При первом запуске придумайте пароль администратора длиной не менее 8 символов. При вводе в консоли символы пароля не отображаются — это нормально.
4. Откройте http://127.0.0.1:8000 в браузере и введите тот же пароль.
5. Чтобы остановить сервер, нажмите Ctrl+C в консоли.

Скрипт запуска ищет Python через `py`, `python`, затем использует локальный Python Codex, если он есть. Если Python не найден, установите Python 3.10+ и повторите запуск. Не закрывайте консоль во время работы.

При первом запуске автоматически создаются **7 отдельных баз SQLite** в каталоге `data/`. Для загрузки вымышленных демонстрационных данных нажмите «Загрузить пример» на главной странице или запустите `python app.py --demo`. Пароль администратора задаётся вами при первом запуске. Демонстрационные отметки ВАК/Scopus не являются сведениями о реальных публикациях.

## Запуск из терминала

```bash
git clone https://github.com/DizzDer/cafedra.git
cd cafedra
```

Откройте терминал в папке проекта:

```powershell
python app.py
```

Если порт занят:

```powershell
python app.py --port 8001
```

Тогда откройте http://127.0.0.1:8001. Для пустой базы используйте другой каталог данных:

```powershell
$env:ARM_DATA_DIR = "$PWD\my-data"
python app.py
```

`python app.py --demo` добавляет учебные данные только при отсутствии магистрантов. В пустой системе та же операция доступна кнопкой «Загрузить пример». Даты примеров рассчитываются относительно дня загрузки.

## Возможности

- Профили магистрантов: добавление, редактирование, удаление, программа, руководитель, год поступления и статус.
- Учёт дисциплин, семестров, попыток экзамена, баллов и результатов. В примере используется шкала 0–100; проходной балл автоматически не определяется.
- Темы магистрских диссертаций, статусы согласования и история изменения названия.
- Публикации с несколькими авторами, DOI, отдельными отметками ВАК и Scopus и ручным подтверждением. Нормализация DOI и защита от его повторного ввода.
- Ежегодная аттестация, результаты и календарные сроки.
- Напоминания внутри системы при достижении порогов 30, 7 и 1 день, а также при просрочке. Проверка каждую минуту, пока Python-сервер запущен, и при загрузке данных интерфейсом.
- Автоматическое составление индивидуального плана, редактирование работ, сроков и выполнения, согласование и утверждение.
- Новая версия при каждом формировании. Содержание утверждённой версии защищено от изменения и удаления.
- Экспорт документов в DOCX, печать в PDF через браузер и экспорт списков в CSV, поиск по разделам.
- Пароль администратора, защищённый хеш пароля, серверная проверка данных, защита запросов изменения от CSRF и журнал операций.

## Где находятся базы данных

Все файлы находятся в `data/` рядом с `app.py`:

| Файл | Таблицы | Назначение |
|---|---|---|
| StudentsDb.sqlite3 | students | Магистранты |
| ExamsDb.sqlite3 | exams | Экзамены и попытки |
| TopicsDb.sqlite3 | topics, topic_history | Темы и история |
| PublicationsDb.sqlite3 | publications, authors | Публикации и соавторы |
| AttestationDb.sqlite3 | attestations, notifications | Аттестации и напоминания |
| PlansDb.sqlite3 | plans, plan_items | Версии планов и работы |
| AuditDb.sqlite3 | audit_events, organization_settings, documents, assistant_proposals | Журнал, реквизиты, реестр и предложения помощника |

Базы можно открыть любым просмотрщиком SQLite. Файлы в `schema/` содержат SQL определения таблиц и индексов. Схема связей и API описаны в `ARCHITECTURE.md`.

Базы **настоящие**: данные читаются из SQLite и сохраняются после закрытия браузера и перезапуска программы. `student_id` связывает модули логически; существование магистранта проверяет Python. Внешние ключи SQLite работают внутри одной базы. Магистранта со связанными записями удалить нельзя.

## Сценарий для защиты

1. Откройте «Обзор»: покажите статистику, сроки и напоминания.
2. В «Магистранты» добавьте свой тестовый профиль.
3. Добавьте этому профилю диссертацию и экзамен.
4. Зарегистрируйте публикацию; можно выбрать сразу нескольких авторов с Ctrl.
5. Назначьте аттестацию через 7 дней и вернитесь в «Обзор». Появится уведомление.
6. В «Индивидуальные планы» выберите магистранта и учебный год, например 2026/2027. Сформируйте план, откройте его и проверьте работы.
7. Сохраните статус «На согласовании», затем «Утверждён». Нажмите «Документ» и подготовьте версию для Word в реестре. Изменить содержание утверждённой версии плана уже нельзя.
8. В «Базы данных» покажите раздельные файлы, затем в «Журнал действий» — выполненные операции.
9. Перезапустите приложение и убедитесь, что записи сохранились.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

26 автоматических тестов используют временные базы и не изменяют данные проекта. Проверяются HTTP-вход и CSRF, сохранение, дубликаты, связи, история тем, уведомления, версии планов, DOCX и учебный набор данных.

## Резервное копирование

Остановите сервер и скопируйте **всю папку data**. Для восстановления при остановленном сервере замените её копией. Не копируйте только одну базу: между файлами есть логические связи. Файл `auth.json` содержит соль и хеш пароля, поэтому его также нужно сохранять приватно.

## Границы учебной версии

Это локальный проект с одной ролью администратора. Он слушает только 127.0.0.1. Отдельные аккаунты магистрантов и руководителей, распределённые транзакции, публикация в интернете, электронная почта, загрузка файлов и реальная интеграция со Scopus не реализованы. Напоминания видны внутри приложения; при выключенном сервере они не отправляются, а актуальный порог обрабатывается при следующем запуске.

В исходном отчёте предлагались ASP.NET Core MVC и PostgreSQL. Здесь по согласованному выбору используются Python и отдельные SQLite-файлы: функциональные задачи сохранены, техническая реализация отличается. Для магистратуры кандидатские минимумы заменены на дисциплины и экзамены. Докторантура как отдельный учебный процесс в эту версию не входит.

Публикации имеют только год, поэтому при генерации плана выбираются статьи из обоих календарных лет учебного периода; их применимость следует проверить вручную. План — сохранённый снимок работ, он не обновляется автоматически при изменении исходного экзамена или статьи. Для обновления создайте новую версию. DOCX содержит текстовый план, а не университетский бланк с нормативным оформлением.

```text

├── app.py             # HTTP API, сервисы, создание баз и напоминания

├── assistant_service.py # Сводки, API модели и подтверждаемые действия

├── schema/            # SQL-схемы семи баз данных
├── tests/             # Автоматические проверки
├── start.bat          # Запуск в Windows
├── ARCHITECTURE.md    # Архитектура, ER-диаграмма и API
├── requirements.txt  # Сторонние зависимости не требуются
└── data/              # Создаётся при запуске; исключён из Git
```
